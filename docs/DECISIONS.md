| D-11 | 2026-11-06 | **Architecture: four agents, each one Claude Agent SDK session (`claude_agent_sdk.query`) with its own context, its own system prompt and a limited tool list.** The tools are served by an in-process SDK MCP server (`create_sdk_mcp_server`, `triage.tools`): Enricher gets `lookup_company` only; Qualifier gets `evaluate_fit` only (G0 `evaluation` with `g2_lead_fit_v1`); Drafter gets `check_consent`, `check_brand`, `check_claims` only; the Orchestrator gets `find_duplicates` only and returns a plan. | D-12 | 2026-11-06 | **The orchestrator decides in two places, on purpose.** The Orchestrator *agent* reads the lead and returns a plan: call or skip the Enricher (skip when the contact already carries company, industry, size and website, D-19), call or skip the Qualifier, and a one-line reason for each. The *crew* (code) applies the hard rules that no plan may override: a duplicate (D-14) skips every worker; an unresolved company skips the Qualifier and the Drafter; the Drafter runs **only** for band `good fit` **and** `audience_consent.allowed`; at `over_cap` no further model is called. **Every skip is logged** through `observability` with `status="skipped"` and the reason in `note`, and listed in the triage note (PRD AC 3). | PRD: "the orchestrator chooses which specialist to call". The model chooses where judgment helps; code decides where a wrong choice would break an invariant. |
| D-13 | 2026-11-06 | **Score and band.** Score (0–100) = `evaluation.total × 100` for rubric `g2_lead_fit_v1` (criteria and weights in `rubrics/lead_fit_v1.json`; pass threshold 0.8 and the required criteria decide `passed`).
