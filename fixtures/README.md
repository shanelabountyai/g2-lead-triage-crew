# Fixtures

Everything here is invented. Names end in `-person`, emails are on `example.com` (RFC 2606), companies live on `*.example.com` / `*.example.edu` domains. No real contact data may be added to this folder (same rule as G0, D-9).

| File | What | Who reads it |
|---|---|---|
| `leads.json` | 20 synthetic HubSpot contacts with the properties the Stalled-Pilot Diagnostic writes (`li_tool_*`, see `li-lead-gen-tools/src/lib/hubspot.ts`), the standard properties HubSpot may already hold (`lastname`, `jobtitle`, `industry`, `numberofemployees`, `website`) and a `message`. Each carries a hand `label` with the expected band: **the eval set** (PRD AC 5). 8 good fit, 4 poor fit, 2 student, 2 vendor, 2 duplicate, 2 missing company info. | `FakeHubSpot` (seeded with them), `triage replay`, `triage eval`, the tests |
| `companies.json` | The synthetic company directory: 13 organizations with industry, size band, head-count, kind (`company`, `education`, `vendor`) and aliases. | The Enricher's `lookup_company` tool, and nothing else (D-6: no web lookup) |
| `recorded-responses.json` | One structured answer per agent per lead, keyed `<agent>:<lead_id>`, replayed by `RecordedCaller` when no `ANTHROPIC_API_KEY` is present. **Generated by `make-recorded.py` from the lead fields with plain heuristics; it never reads the labels and it is not a recording of a live model** (D-16). `triage run --fixtures --record` with a key overwrites it with real responses. | `RecordedCaller` |
| `make-recorded.py` | The generator for the file above. `uv run python fixtures/make-recorded.py` rewrites it deterministically. | — |

Why the emails reuse G0's seeded contacts: `audience.consent` only knows the 20 synthetic contacts in `g0-shared-layer/src/shared_layer/seeds/contacts.json`. A lead whose email is not there is `unknown_contact` and never gets a draft. The eight good-fit leads use G0 emails on purpose, two of them (`cleo.test03`, not consented on email; `gia.test07`, do-not-contact) so the consent gate is exercised (D-15).
